# 가명키 매핑표 — 대외 반출 금지

`delivery/` 패키지의 마이크로데이터는 원본 식별자를 대체키로 치환한 **가명 정보**입니다.
이 폴더의 매핑표는 그 대체키를 원본으로 되돌릴 수 있는 유일한 수단이므로
**연구원 내부에서만 보관하고 업체를 포함한 외부에 전달하지 않습니다.**

| 파일 | 내용 |
|---|---|
| `id_mapping_school.csv` | `학교ID`(SCHID) ↔ `학교키`(SCH001~) — 180개교 |
| `id_mapping_respondent.csv` | `조사연도` + `응답자ID`(STUID/TID) ↔ `응답자키` — 22,859건 |

## 왜 치환했는가

원본 `STUID`는 `SCHID × 10000 + 학교 내 순번` 구조여서 학생 ID만 봐도 학교가 드러납니다.
반면 집계에는 응답자ID·학교ID가 **전혀 사용되지 않습니다**
(집계 그룹 기준은 `indicator_id + 조사연도 + 지역규모코드`이며 지역규모는 이미 결합되어 있음).

즉 업체가 원본 식별자를 보유할 이유가 없으므로 제거했습니다.

## 대체키 설계

| | 규칙 | 보존되는 것 |
|---|---|---|
| `학교키` | 주기 무관, 동일 학교에 동일 키 | 학교 단위 시점 간 추적 |
| `응답자키` | 주기 내에서만 유효. 주기별로 ID 값을 매핑 | 동일 주기 내 학생–학부모 쌍 연결 |

원본 순서가 드러나지 않도록 고정 시드로 섞어 부여했습니다(재현 가능).

## 유의

가명 처리는 **익명 처리가 아닙니다.** 개인정보보호법상 가명정보는 여전히 개인정보이며,
응답 패턴 조합에 의한 재식별 가능성은 남아 있습니다.
따라서 마이크로데이터 자체의 취급 기준(보안서약서·접근 통제·보관 기한)은
가명 처리 여부와 무관하게 그대로 적용되어야 합니다.
